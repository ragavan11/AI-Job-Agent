# Personal Job Agent — Phase 1

A real, working job-search assistant for one person (you): it pulls live
postings from five sources, scores them against your profile, and
generates tailored resumes and cover letters with AI. No mock data —
every job you see came from a real API call.

This is **Phase 1** of a larger plan. See [ROADMAP.md](./ROADMAP.md) for
what's here versus what comes later (wider job-source coverage, the
application-tracker dashboard, assisted apply-automation with a required
review step, and the rest).

## What's actually in Phase 1

- **Job aggregation** from Greenhouse, Lever, Ashby, RemoteOK, and
  Himalayas — all public, unauthenticated, ToS-friendly APIs. No
  scraping, no browser automation, no login.
- **Matching engine** — deterministic skill / location / salary /
  experience scoring, explained in `backend/app/matching.py`.
- **AI resume tailoring** — creates a new resume tailored to a specific
  job from your master resume. Never invents experience; only
  reorders/rephrases what's true, and tells you what's still missing.
- **AI cover letter generation**, grounded in your real profile.
- **PDF / DOCX export** for both.
- **Application tracker** — save jobs, update status, see response/success
  rate.

## What's deliberately NOT in Phase 1

LinkedIn, Indeed, Naukri, Glassdoor, and Workday-based company sites
aren't wired up yet, and there's no browser-automation "apply" engine.
That's Phase 2/3 — both involve real tradeoffs (ToS enforcement risk on
the big platforms, and the fact that fully-automatic submission is
actively working against applicants right now) that are worth building
deliberately rather than bolting on. See ROADMAP.md.

## Requirements

- Docker and Docker Compose (recommended), **or** Python 3.12+ and
  Node.js 20+ if you'd rather run things directly
- An API key for at least one of: Anthropic, OpenAI, Gemini

## Setup

```bash
./scripts/setup.sh
```

This generates a shared auth token and creates `.env`, `backend/.env`,
and `frontend/.env.local` from their `.example` files. It's safe to
re-run — it won't overwrite files that already exist.

Then:

1. Open `backend/.env` and add your AI provider's API key
   (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, or `GEMINI_API_KEY` — only the
   one matching `AI_PROVIDER` is required).
2. Open `backend/app/tracked_companies.json` and add the companies you
   actually want to track on Greenhouse/Lever/Ashby (see the comment in
   that file for how to find a company's token). Greenhouse, Lever, and
   Ashby don't have a global search API — each endpoint returns *one*
   company's postings, so this list is what determines your coverage on
   those three sources. RemoteOK and Himalayas are global feeds and need
   no configuration.

Then run it:

```bash
docker compose up --build
```

- Backend: http://localhost:8000 (interactive API docs at `/docs`)
- Frontend: http://localhost:3000

First run: open the frontend, fill in your profile (this is what every
score and every generated document is based on), then click **Refresh
jobs**. After that, it refreshes itself automatically every
`AUTO_REFRESH_MINUTES` (default 60).

### Running without Docker

```bash
# backend
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload

# frontend, in a second terminal
cd frontend
npm install
npm run dev
```

## Verifying it on your machine

I built and tested everything I could from this sandbox — but this
sandbox's network allowlist doesn't include job-board APIs or Google
Fonts, so two things are worth checking on your first real run:

- **`docker compose up --build` completes and both health checks pass**
  (`curl localhost:8000/health`). The backend's own test suite
  (`cd backend && pytest`) passes 22/22 here, including mocked tests of
  every job-source parser against each API's documented response shape
  — but "documented shape" and "what the API actually returns today"
  can drift. If a source comes back empty after a refresh, check the
  backend logs — a schema mismatch will show up there as a specific
  per-source error rather than crashing the whole refresh.
- **The Google Fonts `<link>` in `frontend/app/layout.tsx`** needs
  normal internet access in the browser (it does, unlike this sandbox).
  If you're running somewhere offline, delete that `<link>` tag and the
  Tailwind font stack falls back to system fonts automatically.

## Security notes

- The API requires a bearer token (`API_AUTH_TOKEN`) on every request —
  generated by the setup script, checked with a constant-time
  comparison. There's no multi-user login by design (see below), but an
  unauthenticated local API is still worth locking down.
- `.env` files are gitignored. Nothing sensitive is hardcoded anywhere
  in the source.
- AI provider keys never leave your machine except to call that
  provider's own API.

## Why this stack is lighter than the original spec

Postgres, Redis, Celery, and full OAuth/JWT/role-based access are built
for a multi-user SaaS product. This runs on one machine for one person,
so it uses SQLite, an in-process scheduler (APScheduler), and a single
shared-secret token instead. Same functionality, far fewer moving parts
to run and debug. `DATABASE_URL` in `backend/.env` is a one-line change
to point at Postgres instead if you ever do need it.

## Project structure

```
backend/
  app/
    job_sources/     # one client per source + the aggregator
    ai_engine/        # provider-agnostic LLM interface + resume/cover-letter logic
    routers/          # FastAPI route handlers
    matching.py        # deterministic scoring engine
    models.py / schemas.py / database.py / config.py / auth.py
    pdf_export.py / docx_export.py
  tests/               # 22 tests: matching logic, source parsing, API integration
frontend/
  app/                 # dashboard + profile pages (Next.js App Router)
  components/          # JobCard, ScoreBars, SummaryStrip
  lib/api.ts           # typed API client
scripts/setup.sh        # one-command env setup
docker-compose.yml
```
